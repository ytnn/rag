## Работа с ботом

В начале необходимо указать Open AI API-KEY  в docker-compose.yml и rag_bot.py

**Для запуска в докере** сначала сбилдить образ:


``docker compose build``

Потом запустить:


``docker compose run --rm -it rag-bot``

**Для запуска вручную** зайти в папку src, выбрать соответствующий файл и запустить его, установив зависимости.

## Задание 1. Исследование моделей и инфраструктуры


### 1. Сравните LLM-модели: 


| Параметр | Локальные модели (Hugging Face) | Облачные модели (OpenAI / YandexGPT) |
|----------|--------------------------------|-------------------------------------|
| **Качество ответов** | Зависит от конкретной модели и дообучения. Например, Llama 3 (8B, 70B, 405B) — большие модели обычно дают более качественные ответы, но без дополнительного обучения могут не понимать контекст диалога идеально. Дополнительный плюс — полный контроль над данными | Модели уже оптимизированы, высокое качество из коробки, хорошо справляются с генерацией текстов, логикой, контекстом и инструкциями. |
| **Скорость работы** | Сильно зависит от железа: CPU работает медленно, на GPU быстрее. | Высокая и предсказуемая скорость, так как облачные сервисы масштабируются автоматически. |
| **Стоимость владения и использования** | Высокая: нужно покупать GPU, оплачивать электричество, обслуживание и лицензии, а также поддерживать инфраструктуру, но меньшие расходы при высоком трафике.  | Оплата по использованию: платишь за API-запросы. Нет расходов на железо, электроэнергию и поддержку инфраструктуры, но может стать дорого при большом объёме запросов. |
| **Удобство и простота развёртывания** | Требует настройки окружения: Python, библиотеки, Docker, оптимизация под CPU/GPU. | Быстрое подключение через API: достаточно апи-ключа, минимальная настройка. Нет необходимости держать инфраструктуру и управлять серверами. |

### 2. Сравните модели эмбеддингов: 


| Параметр | Локальные Sentence-Transformers | Облачные OpenAI Embeddings |
|----------|-------------------------------|---------------------------|
| **Скорость создания индекса** | Быстро на GPU, медленно на CPU| Быстро, производительность масштабируется в облаке |
| **Качество поиска** | Хорошее, особенно при дообучении| Высокое качество|
| **Стоимость владения и использования** | Значительные начальные затраты: железо + ПО. Высокие затраты на электроэнергию. | Платишь только за доступ к API, но стоимость растёт при больших объёмах запросов. |

### 3. Сравните векторные базы ChromaDB и FAISS:


| Параметр | ChromaDB | FAISS |
|----------|----------|-------|
| **Скорость поиска и индексации** | Высокая на небольших и средних объёмах данных| Очень высокая, особенно на больших данных|
| **Сложность внедрения и поддержки** | Простая интеграция через Python API| Требует понимания индексов, нормализации векторов и типов поиска |
| **Удобство в работе** | Встроенные функции: сохранение, загрузка, обновление, поддержка SQLite/Postgres как бэкенд| Работа на низком уровне: нужно самостоятельно управлять сохранением, нормализацией, выбором метода поиска |
| **Стоимость владения (учёт инфраструктуры)** | Нет обязательных затрат на железо, легко развернуть локально или в облаке.Для больших проектов может понадобиться мощный сервер или облако. | Развертывание на больших данных требует хорошее железо (CPU/GPU)|

### Варианты развёртывания RAG-бота 


| Вариант                    | Состав                                                                | Плюсы                                                                                    | Минусы                                                                                                               |
| -------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Облачный**               | LLM OpenAI + OpenAI Embeddings + FAISS            | Быстрый запуск без настройки железа, стабильное качество ответов, масштабируемость              | Высокая стоимость при большом объёме запросов, зависимость от облачного провайдера, возможный запрет обработки конфиденциальных данных                                        |
| **Гибридный**              | LLM: облачный OpenAI + локальный small Llama (LLaMA3 13B) для внутренних/чувствительных задач. Embeddings: локальные Sentence-Transformers для чувствительных данных; OpenAI Embeddings для публичного слоя + FAISS | Сбалансированное качество и контроль данных, подходит когда часть контента конфиденциальна, обеспечивает экономию финансов при росте запросов. | Требует настройки двух систем, сложнее поддерживать, нужна локальная GPU для LLM                                          |
| **Локальный** | LLM: Llama 70B + Sentence-Transformers GPU+ FAISS | Полный контроль над данными, высокая безопасность, независимость от облака                      | Дорогой запуск, сложная установка и настройка, возможно более низкое качество генерации по сравнению с облачными моделями |

Лучшее решение - гибридный вариант, поскольку он обеспечиваеет баланс приватности и скорости внедрения, позволяет обрабатывать локально конфиденциальные данные,а публичные данные могут обрабатываться облачным LLM для экономии на GPU. 
Это минимизирует риски утечки и даёт гибкость и масштабируемость. Для быстрого старта и показа MVP можно задействовать облачный вариант, исключив из обработки конфиденциальные данные.
